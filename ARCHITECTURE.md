# Architecture

This project uses LiveKit Agents in a cascaded pipeline, as required by the challenge: Deepgram performs streaming speech-to-text on the practice agent's audio, OpenAI generates the patient simulator's next utterance, and Cartesia synthesizes the patient voice. The LiveKit worker starts its `AgentSession` before dialing so the bot does not miss the first greeting from the assessment line. Outbound telephony is handled with LiveKit SIP: each run creates a dispatch for a unique room, and the worker adds the fixed SIP participant `+1-805-439-8008` through the configured outbound trunk. A hard-coded destination guard refuses to call any other number.

The bot is scenario-driven rather than a one-off script. `scenarios.json` defines patient personas, facts, goals, and edge-case behaviors, while `run_calls.py` dispatches the minimum 10 calls with spacing so each conversation can finish cleanly. Transcripts are written from LiveKit session events into `artifacts/transcripts`, then `analyze_transcripts.py` can turn those transcripts into a bug report. I chose this structure because the reviewer cares most about coherent calls and clear iteration: the scenario file makes coverage obvious, the agent code stays small, and the artifacts map directly to the submission checklist.
